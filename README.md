# 十里方圓｜角色人生模擬遊戲（第一版）

手機優先的 8-bit 像素風網頁遊戲。玩家抽到一個身分，在 5 天裡每天遇到一件大家共同的事，並與另一個角色對話，最後得到結局（一群人的故事）。
目前可玩 3 個角色：在地小農、合作社社員、消費者（抽角色時三選一隨機），各有自己的 5 天劇情與結局文字；其餘 5 個角色（簡報的角色設計方案）顯示為即將開放。

> ⚠ 所有角色、事件與數值皆為**虛構模擬**，劇情文字尚待合作社校正，請勿當成合作社真實發生的事。

## 執行

需要 Node.js 18 以上。

```bash
npm install
npm run dev      # 開發，開啟顯示的網址（手機請用同一個 Wi-Fi 的區網網址）
npm run build    # 打包到 dist/
npm run check    # 檢查對話資料（每則數值總和為 0、3 問 × 3 回），並確認每個角色 7 種結局都能到達
```

## 規則（由程式控制）

- 三個數值：**生活餘裕、社群連結、資源效率**，開局各 5，範圍 0–10（超出取上下限）。
- 每個選項三項變化總和為 0（有得有失）。畫面只顯示數值條與「增加／略減」，不顯示精確數字。
- **目前玩法（共同故事模式）**：每天一件共同事件（旁白）→ 一段兩兩對話。對話資料在 `src/data/pairs.ts`（對照 Excel「對話樹表」，共 15 組、每組 3 問 × 每問 3 回覆）。
  - 玩家是**提問者**：自己選 1 個問題，對方的回覆從該問題的 3 種回覆中隨機抽。
  - 玩家是**回覆者**：對方的問題隨機抽，玩家從 3 種回覆選 1。
  - 每個回覆各有「提問者／回覆者」兩組數值變化，各自總和為 0。
  - 每天從「有玩家角色在內的對話組合」隨機抽 1 組（每個角色每天有 2 組）。
- 舊的單人事件池（`farmer.ts`、`member.ts`、`consumer.ts`、`dialogues.ts` 等）仍保留在專案中，目前未使用。
- 結局依序判定，符合就停：
  1. 生活餘裕 = 0 → 撐不下去的一週
  2. 社群連結 ≤ 3 → 一個人的田
  3. 資源效率 ≤ 2 → 滿手收成用不完
  4. 最高的數值有兩項以上並列 → 各有取捨的一週
  5. 生活餘裕最高 → 穩穩過日子
  6. 社群連結最高 → 有人一起的田
  7. 資源效率最高 → 精打細算的一週

## 專案結構

```
src/
  data/
    roles.ts      8 個角色（playable 決定是否可玩）
    farmer.ts     小農 5 天劇情：原本的 7 個事件、選項、數值變化、選項意圖
    farmerExtra.ts 小農新增的 8 個事件（尚待合作社校正）
    member.ts / consumer.ts  社員、消費者的 5 天劇情（來自 Excel 社員場景表、消費者場景表，尚待合作社校正）
    scripts.ts    各角色劇情與開場的對照表（新增角色在這裡加）
    roleTexts.ts  各角色的開場文字與結局文字
    pairs.ts      共同事件旁白與兩兩對話樹（目前使用）
    dialogues.ts  舊版角色對話（未使用）
    endings.ts    7 種結局文字
  engine/
    game.ts       開局、套用選項、結局判定、數值轉文字
    textProvider.ts   文字來源介面（第一版回傳固定文字，日後換成 AI）
  components/     PixelCharacter、Scene、Meters、DialogBox
  screens/        開始、角色抽取、角色故事、共同事件、兩兩對話、結局（情境選擇、舊對話頁未使用）
  styles.css      配色與像素風樣式（森林綠 #426B53、淺草綠 #A8B99A、奶油米白 #F6F0DE、暖橘 #DDA36C、木質棕 #80634C）
scripts/check-data.ts   資料檢查
```

## 新增角色

1. 在 `src/data/` 新增該角色的劇情檔（格式同 `farmer.ts`）。
2. 在 `src/data/roles.ts` 把該角色的 `playable` 改為 `true`。
3. 在 `src/App.tsx` 的 `scripts` 對應表加上該角色。
4. 執行 `npm run check`，確認數值總和與結局可到達。

## 日後接 AI（約 12/10）

AI **只改寫文字**，不能更動數值、結局或選項數量。

1. 在 `src/engine/textProvider.ts` 新增一個 provider，呼叫自己的後端函式（例如 Vercel Function）。**API 金鑰只放後端，不可放進前端程式碼。**
2. 傳給 AI 的資料只有文字：事件類型、固定原句、三個選項的意圖、三個數值的文字狀態（偏低／普通／偏高）、前幾天選擇摘要。不傳數字。
3. 要求 AI 回傳 JSON：`{ situation, options: [{id, text}] }`。
4. 驗證：恰好 A/B/C 三個選項；情境 60–90 字；選項 25 字內；不含阿拉伯數字與金額；不含「最好／最佳／明智／應該／正確／一定」。
5. 驗證失敗重試一次，仍失敗就退回固定版文字。
6. 把檔案最後一行 `textProvider` 換成新的 provider。
